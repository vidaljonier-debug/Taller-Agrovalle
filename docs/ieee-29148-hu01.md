# Especificación de Requerimientos: Comparativa BDD vs. Estándar IEEE 29148 (HU-01)

## 1. Enfoque Ágil (Historia de Usuario + BDD)
- **Identificador:** `HU-01` — Registro de Agricultores.
- **Narrativa:** Como agricultor del Valle del Cauca, quiero registrarme en la plataforma con mi nombre, municipio y cédula para poder publicar mis cosechas directamente sin intermediarios.
- **Criterios de Aceptación (Given-When-Then):**
  - **Given:** Un nuevo productor con datos válidos (`nombre`: "Juan Perez", `municipio`: "Dagua", `cedula`: "1144001122").
  - **When:** Envía una petición `POST` a `/api/v1/auth/register`.
  - **Then:** El sistema responde con `HTTP 201 Created`, persiste el registro en PostgreSQL y retorna su identificador único.

---

## 2. Especificación Formal (Estándar IEEE 29148 / SyRS)
- **Código de Requerimiento:** `REQ-FUNC-001`
- **Título:** Registro de Productor Agrícola en el Sistema.
- **Descripción Funcional:** El sistema deberá proporcionar un servicio web RESTful que permita el alta de productores agrícolas ubicados en municipios del Valle del Cauca, validando la unicidad de su documento de identidad y almacenando su perfil de forma persistente en la base de datos relacional.
- **Entradas:** Petición HTTP `POST /api/v1/auth/register` con carga útil JSON (`application/json`):
  - `nombre` (`VARCHAR(120)`): Nombre completo del agricultor. Obligatorio, no vacío.
  - `municipio` (`VARCHAR(80)`): Municipio del Valle del Cauca donde opera. Obligatorio, no vacío.
  - `cedula` (`VARCHAR(20)`): Número de identificación del productor. Obligatorio, único en el sistema.
- **Salidas:**
  - *Caso exitoso:* Respuesta HTTP `201 Created` con cuerpo JSON que incluye el `id` autoincremental generado (`BIGSERIAL`) y los datos registrados.
  - *Caso de error de validación:* Respuesta HTTP `400 Bad Request` si algún atributo obligatorio es nulo o incumple formato.
  - *Caso de duplicidad:* Respuesta HTTP `409 Conflict` si el valor de `cedula` ya existe en la tabla `agricultor`.
- **Restricciones y Reglas de Negocio:**
  - La columna `cedula` debe poseer restricción `UNIQUE` a nivel de motor PostgreSQL.
  - La transacción debe garantizar propiedades ACID mediante Spring Data JPA.
- **Criterios de Verificación:** Ejecución automatizada de pruebas unitarias y de integración en **JUnit 5 + MockMvc** validando código de estado `201 Created` para registros nuevos y rechazo ante cédulas duplicadas.
