# Sprint 1 — Retrospectiva

## Qué funcionó
El equipo logró establecer una base técnica consistente para el proyecto, con Java 17, Spring Boot, Checkstyle, JUnit 5, JaCoCo, Husky y GitHub Actions. La separación Controller → Service → Repository permitió dividir el trabajo por historia y facilitar la revisión por pares.

## Qué se debe mejorar
La planificación inicial incluía funcionalidades del catálogo que dependían de datos de cosechas todavía no disponibles. Esto generó una dependencia que debía detectarse antes de comprometer el Sprint.

## Acción de mejora
Para el siguiente Sprint, el equipo deberá validar las dependencias de datos y de negocio antes del Planning Poker y reservar las funcionalidades de catálogo avanzado para después de la publicación de ofertas.

## Decisiones para Sprint 2
Se priorizará la publicación de cosechas/ofertas y posteriormente la integración del filtro por categoría con la búsqueda por municipio.
